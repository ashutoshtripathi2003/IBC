# Database

PostgreSQL (16 locally and in CI) is the transactional source of truth.

## Rules

- Every schema change is a new file in `apps/api/migrations/` named `NNNN_description.sql`.
- Migrations are **forward-only** and run in order, each in its own transaction, under a
  PostgreSQL advisory lock (safe when several pods start at once).
- The migrator stores a SHA-256 checksum of each applied file and **refuses to run if an
  applied migration was edited** or if the database has a migration the code does not.
- Never change production schema by hand. Destructive changes (drop/rename column or table,
  type narrowing) require founder approval and an expand → migrate → contract plan.
- Each domain module owns one PostgreSQL schema; no other module may reference it in SQL.
- Every migration file starts with an `-- Owner:` and `-- Purpose:` header.
- Document every change in this file in the same commit.

Run: `pnpm db:migrate` (dev, from sources) or `node dist/migrate.js` (built image).

## Conventions

| Concept                       | Convention                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------------- |
| Primary keys                  | `uuid`, UUIDv7 generated by the application (`@ibc/kernel`)                         |
| Timestamps                    | `timestamptz`, UTC; `created_at`/`updated_at`                                       |
| Money                         | `amount_minor bigint` + `currency char(3)` (ISO 4217); never float/numeric-as-float |
| Country                       | `char(2)` ISO 3166-1 alpha-2                                                        |
| Locale                        | BCP 47 text; timezone = IANA name                                                   |
| Enumerations                  | `text` + `CHECK` constraint (cheaper to evolve than PG enums)                       |
| Tax/registration IDs (TARGET) | generic `(country, registration_system, value)` rows, never GST/PAN/CIN columns     |

## Schemas and tables (CURRENT)

### `platform` — owner: platform

| Table               | Purpose                                                                                                                                                                                                                                         |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schema_migrations` | Applied migration versions + checksums (created by the migrator)                                                                                                                                                                                |
| `outbox_events`     | Transactional outbox. Columns: `id, aggregate_type, aggregate_id, event_type, event_version, payload jsonb, metadata jsonb, occurred_at, published_at, attempts, next_attempt_at, last_error, dead_lettered_at`. Partial index on pending rows. |

### `audit` — owner: platform

| Table             | Purpose                                                                                                                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `security_events` | Append-only security audit log (`action, outcome ∈ {success, failure, denied}, actor_user_id, subject_id, ip, user_agent, request_id, details jsonb`). A trigger rejects UPDATE and DELETE. |

### `identity` — owner: identity module

| Table                  | Purpose                                                                                                                                                                                               |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `users`                | Account: `email`, `email_normalized` (unique), `email_verified_at`, `display_name`, `status ∈ {active, suspended, deactivated}`, `locale`, `timezone`, `country_code` (nullable — no country assumed) |
| `password_credentials` | `user_id` → scrypt hash (self-describing format). Separate from `users` so passkeys/OIDC/TOTP can be added as further credential tables                                                               |
| `sessions`             | Opaque sessions: SHA-256 `token_hash` (unique), `expires_at`, `last_seen_at`, `revoked_at`, `revoked_reason`, `ip`, `user_agent`                                                                      |
| `user_roles`           | Platform RBAC roles (`member`, `platform_admin`)                                                                                                                                                      |

## Known scaling notes

- `users.email_normalized` is globally unique. If users are ever sharded or split by region,
  this requires a global email → user-id lookup service/table.
- `audit.security_events` and `platform.outbox_events` grow unbounded. **TARGET:** time-based
  partitioning plus retention (outbox: delete published rows after N days; audit retention
  period is a compliance decision — **OPEN QUESTION**).
- Login throttling counts recent failures in `audit.security_events` via
  `security_events_subject_idx`; this moves to Redis when load requires.
- Backups/PITR and restore drills are not configured (no production database exists yet).
